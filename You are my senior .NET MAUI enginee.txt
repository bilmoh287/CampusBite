==================================================
1. PROJECT IDEA
==================================================

CampusBite is a mobile platform designed for students and small local campus cafés.

The main real-world problem is that many small cafés currently manage student food orders using notebooks/books or verbal orders. This creates problems with:

- long waiting times
- lost or incorrect orders
- students having to physically visit the café to order
- difficulty knowing what food is currently available
- difficulty communicating price changes
- difficulty notifying students when the café is closed or unavailable
- difficulty tracking orders
- difficulty managing stock, expenses, and sales as the café grows

CampusBite will eventually solve this by allowing students to:

- discover nearby cafés
- view menus
- see current prices
- see food availability
- place orders before arriving
- choose pickup or delivery
- track order status
- receive announcements and price-change notifications
- track food spending and budget

Café managers will eventually be able to:

- manage their café profile
- manage menu items
- change prices
- mark food available/unavailable
- open or close the café
- receive and manage incoming orders
- update order status
- manage inventory
- track expenses and sales
- send announcements

The application should support multiple cafés, with each café having its own menu, prices, availability, orders, inventory, and business data.

8. MVVM RULES
==================================================

Use CommunityToolkit.Mvvm.

Prefer:

ObservableObject
ObservableProperty
RelayCommand
NotifyPropertyChangedFor

Use ObservableCollection when collection changes must update the UI.

Avoid putting business logic directly in XAML code-behind.

Do not put database queries directly inside Views.

ViewModels should coordinate presentation behavior rather than becoming giant classes.

Services should contain appropriate business/application operations.

==================================================
9. DATABASE RULES
==================================================

For Version 1 use:

SQLite + EF Core.

Prefer Code First.

Use:

- entities
- DbContext
- Fluent API when configuration is appropriate
- seed data where useful

Use decimal for monetary values.

Design relationships deliberately.

Explain:

- primary keys
- foreign keys
- one-to-many relationships
- navigation properties
- delete behavior
- indexes

Do not add database complexity without a requirement.
